>
> 本文的**方向性判断**（「一加相机 ↔ 目标机原厂配置不匹配」）成立，但**具体归因错误**：
>
> - 本文把 `SlowMotionCaptureMode.<clinit>` 的 `NumberFormatException: Invalid Size: ""`
>   当作崩溃主因 —— 实测证明它**只是被 App 捕获的 `E` 级日志**，
>   **相机进程从未崩溃**（无 FATAL、无 tombstone，`am start -W` 返回 `Status: ok`）。
> - 真正的失败在 **HAL 层**：一加相机去开 **SAT 多摄逻辑相机（Camera 6）**，
>   CamX 的 `UsecaseSAT` 初始化失败（`CreateMultiCameraResource` 失败），
>   `configureStreams` 返回 **-38 (ENOSYS)** ⇒ 拿不到 buffer ⇒ 黑屏。
> - **对照实验（决定性）**：OpenCamera 打开 **Camera 0**、走 `AdvancedCameraUsecase`，
>   **完全成功并出画面** ⇒ **HAL / cameraserver / 硬件链路 100% 正常**。
> - 深层原因：**`/my_product` 是供体 8T 的分区**（`ro.product.device=OnePlus8T`），
>   提供一加相机；而 `ro.oplus.system.camera.name=com.oplus.camera` 指向不存在的包。
>
> 本文 **§四 修复方案表**（OpenCamera / 刷回 C15 / 提取 OPPO 相机）仍然有效。
> 最终采纳：**方案 A，保留 OpenCamera 兜底**。

## 一、症状

* 打开相机 App **立即退出**（闪退），无法拍照。
* 用户描述：「相机闪退」「我刚才不小心按到不同意，打不开了」。
* 崩溃计数：**无 `FATAL EXCEPTION`**，相机进程没崩，是 **Activity 主动退出**。

> ★ 关键辨析：用户以为是自己点了「不同意」导致的，**实际无关**。
> 用户当时看到的「不同意」弹窗来自 **`com.oplus.cast` / `com.oplus.linker`（OPPO 互联/投屏）**，
> 那是另一个独立问题（见 §6）。相机的故障是结构性的。

## 三、★ 根因

**移植包里带的是「一加 8T 的相机」，而这台 Find X2 Pro 的系统配置期望的是「OPPO 相机」。**

决定性证据：

```
[ro.oplus.system.camera.name]: [com.oplus.camera]     ← 系统期望 OPPO 相机
[oplus.camera.packname]:       []                      ← 却是空的
[oplus.camera.activityname]:   []                      ← 也是空的
```

而设备上实际存在的相机包是：

```
package:com.oneplus.camera            ← 一加相机（8T 的）
package:com.oneplus.camera.service
package:com.oneplus.camera.pictureprocessing
package:com.oplus.engineercamera      ← 工程相机（无 launcher 入口）
```

**`com.oplus.camera` 根本不存在。**

于是形成死结：

1. 系统层面（`ro.oplus.system.camera.name`）认的是 `com.oplus.camera`，找不到；
2. 实际能启动的一加相机，读的是**一加/8T 体系的配置**，而目标机的相机配置在
   `/odm/etc/camera/`（Find X2 Pro 原厂，2025-07-20 时间戳）里，格式/键名对不上；
3. 一加相机取到的「慢动作尺寸列表」是空串 → `Invalid Size: ""` → 组件创建失败 → 预览起不来 → 退出。

### 为什么重刷同一套镜像无法解决

| 分区 | 来源 | 重刷是否改变 |
|---|---|---|
| `system` | 8T 移植包（含 `com.oneplus.camera`） | 重刷后**还是同一个一加相机** |
| `system_ext` | 8T 移植包 | 同上 |
| `product` | **目标机原厂**（含 `OnePlusCamera.apk` 141 MB） | 不刷，不变 |
| `odm` / `vendor` | **目标机原厂**（含 `/odm/etc/camera` 全套算法模型） | 不刷，不变 |

重刷只是把「同样的一加相机 + 同样的原厂 odm 配置」再写一遍，**不匹配的关系原样保留**。

## 四、修复方案（按推荐度）

### 方案 A —— 装第三方相机（最快，保留 Android 16）

装 **OpenCamera**（开源、免费、兼容性好）验证相机硬件链路。
已下载：`09-Magisk/apk/OpenCamera_96.apk`（4,973,923 B，F-Droid 官方源）

```bash
adb install -r ~/Documents/oppo/2026-安卓16/09-Magisk/apk/OpenCamera_96.apk
```

* 若 OpenCamera 能正常预览拍照 ⇒ **证明 HAL / cameraserver / 硬件链路全部正常**，
  问题 100% 出在一加相机 App 自身的配置读取上。
* 缺点：非原厂相机，功能（夜景、人像算法）不如原厂。

### 方案 B —— 刷回 ColorOS 15 官方（最彻底）

回滚包：`~/Documents/oppo/platform-tools/FindX2Pro_ColorOS_15.0.2_Pro_2025.1_20250823_By_Color597.zip`

* 相机、指纹、NFC 等全部恢复原厂。
* 代价：系统降级到 Android 15。

### 方案 C —— 从 ColorOS 15 提取 OPPO 相机装到 A16（折中）

从官方包里解出 `com.oplus.camera`，装进当前 Android 16。

* 优点：保留 A16 + 用原厂相机。
* 风险：A15 编译的 App 跑在 A16 上，可能因 API / privapp 权限白名单失败；
  且 `ro.oplus.system.camera.name` 已经是 `com.oplus.camera`，装上后系统层面天然吻合，**值得一试**。

## 五、教训

1. **「点了不同意」往往是干扰项**。用户对故障的归因常常不准，
   要用日志验证，不要顺着用户的假设走。
2. **跨机型移植时，App 与「目标机原厂配置分区」的耦合是隐蔽杀手**。
   `vendor` / `odm` 保留原厂是对的（否则丢驱动），但**依赖 odm 配置的 App 必须一起换**。
3. **`ro.*.system.camera.name` 这类「系统级指向属性」要作为移植检查项**：
   它指向哪个包，那个包就必须存在。
4. **判断「闪退」先分清是进程崩溃还是 Activity 退出**：
   前者看 tombstone / FATAL，后者看生命周期日志 —— 本例是后者，所以一开始查权限是白费的。

## 六、附：OPPO 互联（cast/linker）的「不同意」问题（独立问题）

现象：打开某些界面后，`com.oplus.cast` / `com.oplus.linker` 的窗口**置顶抢占焦点**，
导致其它 App 看起来「打不开」。

证据：

```
mCurrentFocus=Window{... u0 com.oplus.cast/com.oplus.cast.ui.PrivacyPolicyAlert}
mCurrentFocus=Window{... u0 com.oplus.linker/com.oplus.linker.entrance.ui.EntranceHomeActivity}
```

`/data/user/0/com.oplus.linker/shared_prefs/local_config.xml`：

```xml
<boolean name="cta_dialog_should_show" value="false" />   ← 点了「不同意」后被置为 false
<boolean name="launcher_pre_check_state" value="true" />
<boolean name="first_tile_click" value="false" />
```

处理：`adb shell am force-stop com.oplus.cast; adb shell am force-stop com.oplus.linker`
（不需要 root）。若不需要互联功能，可直接禁用这两个包。
